# protocols/forge — 공방: 수정을 감안해 짓고, 할수록 빨라지게

> **뭐냐:** 모든 갈래에 걸치는 «일하는 법». 한 건을 파이프라인 하나로 짓고(값은 한 곳), 바뀐 단계만 다시 돌리고, 사람이 잡은 결함은 검사로, 통과한 모양·절차는 공용 부품으로, 더 나은 방법은 승패를 세어 공식으로 올린다. 엔진은 `forge/`(`python -m forge`).
> **언제 읽나:** 새 건을 받아 손대기 전(파이프라인 붙이기), 손님 수정이 올 때(값 고치고 `forge run`), 한 건을 넘긴 뒤(부품 올리기·검사 올리기·시도 기록).
> **안 담는 것:** 갈래별 단계와 통과 기준 → 각 `protocols/*.md` · 시행착오 원문 → [`../LESSONS.md`](../LESSONS.md) · 새 시도 대기열 → [`../CHALLENGES.md`](../CHALLENGES.md).

## 왜 (고객K 10-21~22 에서 실제로 시간이 간 곳)

| 일어난 일 | 비용 | 여기서 막는 법 |
|---|---|---|
| 차수마다 spec·dims·build_ai·spec_a 를 v3·v4·v5·v6 로 **복사**해 고쳤다 | 차수마다 같은 일을 다시, 값 하나 바꾸면 파일 8개를 손으로 따라감 | 스크립트는 한 벌, 값은 spec 한 곳, `forge run` 이 바뀐 단계만 |
| 두께 60/70 이 글·치수에 섞였다(사람 격노) | 치수·시안을 다시 보냄 | 보낼 글을 파일로 남기고 `text` 검사(과장 값 금지) |
| 원형 마감이 만든 마름모 앞면 선을 «반사»로 넘겼다(사람이 폰에서 잡음) | 렌더 6장 다시 | `diff` 검사(켬·끔 차이판) |
| 시안 글씨가 선과 겹친 것을 눈 검수가 놓쳤다 | — (검사가 잡음) | `pdf_overlap` 검사 |
| 붙는 자리 모양을 세 번 크게 지었다 | 확대 그림·렌더 세 번 | `confirm` 단계(확대 그림을 먼저 받고 뒤로) |
| 통과한 함수(필렛·발·굽힘·폰 PDF)가 건 폴더에만 있었다 | 다음 건이 다시 지음 | `forge/lib` 로 올리고 건은 import |

## 1. 만들 때 — 수정을 감안해 짓는다

| # | 해라 | 통과 |
|---|---|---|
| 1 | 건 폴더에 `python -m forge init jobs/<건>` → `pipeline.json` 을 이 건에 맞게 고친다(단계 이름·명령·입력·출력) | `forge status` 에 단계가 다 보인다 |
| 2 | **값은 spec 파일 한 곳**(치수·두께·반지름·여백). 단계 스크립트는 spec 을 읽기만 한다. 숫자를 스크립트에 박지 않는다 | 값 하나를 바꾸면 `forge status` 에서 그 값을 읽는 단계가 «바뀜»으로 뜬다 |
| 3 | 단계 입력(`inputs`)에 그 단계가 읽는 파일을 **빠짐없이**(spec, 스크립트, 공용 부품 파일, 손님 원본). 빠지면 바뀌어도 안 돈다 | — |
| 4 | **보낼 글은 파일로 먼저 쓴다**(`--dry` 면 쓰고 끝). 검사가 그 파일을 본다. 보내는 단계는 `"outward": true` | 바깥 단계는 `--send` 없이는 안 돈다 |
| 5 | 모양을 바꾸는 단계 뒤에 **확대 그림 단계 + `"confirm"`**. 확인받기 전엔 렌더·일러로 안 간다 | `[확인 기다림]` 에서 멈춘다 |
| 6 | 부재·절차를 새로 지을 땐 **`forge/lib` 와 방법 대장(`forge method`)을 먼저 본다**. 있으면 import, 없으면 짓고 끝에 올린다 | — |
| 7 | 이미 손으로 만든 결과가 있으면 `forge adopt <건>` 으로 지금 출력을 인정하고 시작 | 모든 단계 «최신» |
| 8 | **비싼 단계(렌더 등)는 spec 파일 통째가 아니라 그 단계가 실제로 쓰는 값만 뽑은 작은 파일을 입력으로**(싼 앞단계가 `args.json` 을 쓴다). 지문은 내용으로 재므로, 값이 같으면 앞단계가 다시 돌아도 비싼 단계는 안 돈다 | spec 의 다른 값을 바꿔도 `forge status` 에서 렌더가 «최신» |

🔴 **차수마다 스크립트를 복사하지 않는다.** 이전 차수 결과는 출력물(드라이브 `시안_MMDD_N차`)로 남기면 된다. 코드 복사는 «어느 쪽이 맞는 숫자냐»를 만든다.

## 2. 할 때 — 더 빠르게를 찾는다

| # | 해라 | 통과 |
|---|---|---|
| 1 | 요구를 받으면 `forge clock start <건> <value·part·format·fix> "<요구 한 줄>"`, 넘기면 `forge clock stop <건> [--accepted no]` | `forge report` 에 한 줄 |
| 2 | 손님 수정은 **spec 값 고치기 → `forge run <건>`**. 멈춘 자리(검사 실패·확인 기다림·바깥 단계)만 사람 일로 처리 | 단계를 손으로 하나씩 돌리지 않는다 |
| 3 | `forge report` 의 «오래 걸리는 단계»와 «안 줄어드는 종류»에서 하나를 골라, 다음 건에서 새 방법을 **기본 길과 나란히**(같은 입력) 해 본다. 후보는 `forge method --queue` 와 CHALLENGES 대기열 | 한 건에 하나 이상 |
| 4 | 결과를 `forge trial <일> <방법> win·loss·tie [--vs 맞붙은 방법] --job --metric "잰 값"` 으로. CHALLENGES 표에 자동으로 한 줄 | 잰 값 없는 판정 금지 |

## 3. 하고 나서 — 남기고, 공식으로

| # | 해라 | 통과 |
|---|---|---|
| 1 | **다른 건에도 쓸 함수는 `forge/lib/` 로 옮기고**, 건 스크립트는 import 로 바꾼다. 옮긴 뒤 출력 지문(sha1)이 옮기기 전과 같은지 대조 | 지문 같음 |
| 2 | **사람이 잡은 결함은 검사로 올린다**(아래 표의 종류로 pipeline 에 넣거나, 새 종류면 `forge/_gates.py` 에). LESSONS 한 줄로 끝내지 않는다 | 같은 결함을 검사가 잡는지 옛 결과물로 한 번 재현 |
| 3 | 방법 대장 규칙: **서로 다른 두 건에서 이기고 진 적 없으면 공식**, 2패면 버림, 사람이 결과물에서 거절하면 한 번에 버림. 공식이 되면 해당 프로토콜 «해라» 칸에 한 줄 + 줄 끝 `{승격: forge method <일>}` | `forge method` 에 공식 |
| 4 | `forge report` 를 한 번 보고, 종류별 시간이 줄지 않으면 그 종류의 막힌 단계를 CHALLENGES 대기열에 한 줄 | — |

## 검사 종류 (`pipeline.json` 단계의 `gates`)

| type | 막나 | 보는 것 | 생긴 사건 |
|---|---|---|---|
| `text` | 막음 | 글(txt·md·pdf)의 Claude 기호·금지 표현(RULES/산출물.md §5), `forbid` 값(정규식, `unless` 예외). 손님 문서엔 우리 쪽 사람 이름도 forbid(`init` 뼈대에 기본으로 들어 있다) | 10-22 두께 70 이 글에 나감 · 시안 출처에 «작업자님 제공» |
| `files` | 막음 | 파일 수·그림 크기·용량 | 10-21 렌더 묶음 검사 |
| `pdf_overlap` | 막음 | 글자끼리 겹침, 가는 선이 글자 몸통을 가로지름, 쪽 밖 | 10-22 전개도 글씨를 D 윤곽이 가로지름, 치수 눈금이 글씨에 닿음 |
| `cmd` | 막음 | 임의 명령(종료코드 0). 식과 **독립인 숫자** 대조에 쓴다 | 10-21 높이 두 번 더함 |
| `graded` | 막음 | 독립 채점(·`need_source` 면 원본 대조) 보고서가 결과물보다 새것이고 «판정:» 이 «고칠 것 있음»이 아닌가. `init` 뼈대의 `graded` 단계(명령 없음, 바깥 단계 바로 앞)에 들어 있다. 보고서가 없으면 «입력이 없다»로 멈춘다 | 10-22 만든 세션이 마름모 앞면 선을 «반사»로 넘김, 10-24 검수 셋(`grade.md`) |
| `zoom` | 보기 | 그림마다 칸을 나눈 확대판 한 장 | 10-21 «4배 확대에서만 보였다» |
| `diff` | 보기 | 옵션 켬·끔 차이를 붉게, 차이 큰 자리 확대 | 10-22 원형 마감이 만든 마름모 앞면 선(사후 재현으로 잡힘 확인) |

## 명령

`python -m forge` (SusannaDesigner 에서) — `run <건> [--only a,b] [--from a] [--force] [--send] [--dry] [--confirm a]` · `status` · `adopt` · `init` · `gate <건> <단계>` · `zoom` · `diff` · `trial` · `method [일] [--queue]` · `clock start|stop` · `report`. `<건>` 은 `jobs/` 아래 폴더 이름.

## 함정
- `pdf_overlap` 헛경보: 글자 상자에 글꼴 위아래 여유가 들어가 위아래 줄이 겹쳐 보였다 → 몸통 높이로 좁혀 잰다. 머리띠의 흰 격자선·로고 밑줄도 걸렸다 → 밝기 0.85 넘는 선은 뺀다.
- 글씨를 옮기면 새 겹침이 생긴다(10-22 두 번째 판에서 두 곳). 고친 뒤 `forge run` 이 다시 잡는다 — 검사를 끄지 말고 간격을 고친다.
- 파이썬 입력의 지문은 주석·설명문을 뺀 코드 구조로 잰다(주석 한 줄에 6분 렌더가 다시 돌던 것을 막음). 반대로 주석에만 적힌 «값»은 지문에 안 잡히니 값은 꼭 코드(변수)로 둔다.
- `run --dry` 는 첫 바퀴만 보인다. 앞단계 출력이 실제로 바뀌는지는 돌려 봐야 안다.
- `adopt` 는 «지금 출력이 지금 입력의 결과»라는 선언이다. 사람에게 실제로 보낸 것이 그 출력과 다르면 쓰지 않는다.
- 방법 대장 `--vs` 는 그 자리에서 실제로 맞붙은 방법만. 사람이 거절했을 뿐이면 `--vs` 없이 `--human`(처음에 거절 셋을 다른 방법의 3승으로 적어 부풀었다).
