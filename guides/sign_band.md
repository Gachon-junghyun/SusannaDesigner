## 1. 원본을 받는다 — 톡클라우드 «작업방»

**해라**
- 크롬(9222)에 **새 탭**으로 `talkcloud.kakao.com` → 로그아웃이면 `로그인` → 저장된 `kakao_id`·`kakao_pw` 를 `Input.insertText` 로 넣는다(값을 화면에 찍지 않는다).
- **2단계 인증**이 뜨면 결재 봇으로 «카톡 확인 버튼 눌러 달라»(`push_text(..., bot='approval')`)를 보내고 3초마다 URL 이 `talkcloud.kakao.com` 으로 돌아왔나 본다(5분).
- 목록은 탭 «안에서» API 로: `v2/mediaFile/list?verticalType=FILE|MEDIA` + `chat/list` 로 방 이름을 붙여 **«수산나디자인 작업방» · 오늘**만 고른다 → `Page.setDownloadBehavior` + 링크 클릭으로 받고 **크기(문자열→int)로 대조**(`kit/sign_band/예시_띠간판/0_*`).
- `.ai` 는 PDF 호환이라 `fitz` 로 바로 열린다 → 미리보기 PNG 를 그려 눈으로 본다.

**통과**: 받은 파일 크기 = 목록 size · 미리보기를 봤다.
**왜**: «이 브라우저에서 2단계 인증 사용 안 함»은 보안을 낮춰 에이전트가 안 누른다. 같은 파일이 다시 올라오기도 한다(10/11 17:02 사진 = 10/10 09:50 현장 사진, 크기·이름 같음) — 크기·이름으로 거른다.

## 2. «난잡»을 숫자로 바꾼다 — 색부터 센다

**해라**
- 손님 `.ai` 를 `page.get_drawings()` 로 돌려 **fill·stroke hex 를 센다.** 래스터 시안이면 `quantize(14)` 로 센다.
- 색마다 **역할**을 붙인다: 로고 빨강 · 상호 빨강 · 띠 · 보조 글자 · 크림 · 먹 · 흰 테 · 치수선(빨강 화살표 `#E71D1B`).
- 사람에게 한 줄: «한 간판에 N색, 그중 거의 같은데 다른 색 쌍이 무엇».

**통과**: 역할 표가 섰다(남는 hex 0).
**왜**: 고객B는 7색이었고, «난잡»의 정체는 **로고 빨강 `#A91D24` 와 상호 빨강 `#B3121A` — 거의 같은데 다른 빨강 둘**이었다. 같은 계열의 «안 맞춘» 두 색이 일부러 고른 대비보다 지저분해 보인다.

## 3. 색 후보 — 로고의 색 안에서, 3색 이내로

**해라**
- 🔴 **처음부터 «3색 이내»로 짠다**(띠 1 + 글자 2, 먹 포함). 로고가 이미 3색이면 **그 3색으로 간판 전체를 돌린다.**
- 색 바꾸기는 **그리기 단위로 다시 그린다**(`kit/sign_band/예시_띠간판/1_역할별_색바꾸기.py`): 역할 표 → 새 hex → `Shape` 로 다시 그림. 레터링·배치는 원본 벡터 그대로.
- **전화번호는 위치로 골라** 띠 대비색으로 따로 칠한다(띠와 같은 색이 되면 사라진다 — 크림 띠 위 흰 번호, 먹 띠 위 먹 번호가 실제로 사라졌다).
- 🔴 **흰 테·흰 조각을 먹으로 바꾸면, 흰 바탕에 숨어 있던 옛 로고 옆 조각이 드러난다** → 로고 자리 근처의 «흰 선만 있는 조각»은 뺀다.
- 조명 채널이면 한 줄 붙인다: **먹색 글자는 밤에 거의 안 빛난다** → 낮·밤이 딴판이 된다.
- 후보는 한 시트(번호 + 색 칩 + hex)로, 폰에 `push_photo` + 한 줄씩 설명 `push_text`.

**통과**: 시트마다 «쓴 색 수 ≤ 3»(4색은 사람이 시킬 때만) · 전화번호가 보인다 · 남은 옛 색 0.
**왜(실제 흐름, 10/11)**:
1. Adobe Color 팔레트 4개를 입힘 → «싹 다 별로, 3개 이내로».
2. 로고 3색으로 5안 → 사람이 셋을 짚음(크림 띠·빨강·먹 / 먹 띠·빨강·크림 / 먹 띠·크림 글자) + «황토는 정말 아님».
3. 먹 띠 + 빨강 채도 낮춤 `#9E3B37` → «빨강이 너무 짙다» — 채도를 낮추면 먹 띠 위에서 **어두워져 묻힌다**(밝기 차가 준다). 낮추려면 밝기를 같이 올려라.
4. 밝은 빨강·주황 7안 → «아직 별로, 다양하게» → 12색(코랄~청록~하늘) → «다 별로, 로고 동그라미부터».
→ 🔴 **색만 바꾸는 판을 세 번 연속 거절당하면 다른 축(로고 모양·크기)을 먼저 제안하라.** 로고를 바꾸자 일이 굴렀고, 사람은 결국 **처음 3색 안(1A)**을 골랐다 — 색이 문제가 아니라 로고가 안 맞았을 수 있다(추정).

## 4. 로고 모양을 바꾼다 — «~처럼»은 실물부터 본다

**해라**
- 사람이 «고객H처럼»·«○○처럼»이라고 하면 **그 레퍼런스의 «실물 사진»**을 먼저 찾거나 달라고 한다. 시안 그림과 시공된 실물이 다르다.
- 원판(동그라미) 로고는 **로고 SVG 부품을 그대로** 원판 위에 앉힌다(`2_원판_외접원.py` → `3_원판_구성.py`):
  그림 전체의 최소 외접원을 재고 **원판 반지름의 94%**로 맞춘다 · 구성은 «그대로 / 지붕 가운데 / 지붕 가운데 크게» · 색은 «크림 원판 / 빨강 원판».
- 원판 지름은 띠 높이에 맞춰 정한다(고객B: 띠 300 → 원판 700, 띠 위아래로 걸침).
- 🔴 **«네모», «그거» 같은 지시어는 어느 그림인지 확인한다.** 손님 시안에 로고가 둘이면 둘 다 «네모»다.

**통과**: 지붕·글자·솥이 원판 안에서 서로 안 닿는다(확대 확인) · 간판 띠에 얹은 모습까지 같이 낸다.
**왜**: 처음엔 «고객H처럼»을 고객H «시안»(가는 금색 테 + 잎이 원 밖으로)으로 읽고 원판 크기 계산을 하다가, 사람이 **실물 사진**(밝은 원판 박스 안에 그림이 다 들어가고 띠 위아래로 걸침)을 보내 방향이 바뀌었다.
«네모도»는 **세로현판**(빗금 지붕·웃는 솥·먹 고객B)을 말한 건데 **도장격자**로 읽어 한 번 다시 만들었다(사람: «아니 네모는» + 캡처).

## 5. 현장 시뮬 — ChatGPT 판 + 실제 비율 합성 «둘 다»

**해라**
- 간판 평면(투명 PNG + 흰 바탕)을 안마다 뽑는다. **현장 사진(표시선 있는 것) 위 + 평면 아래**를 한 장에 묶어 jobs 의 `"ref"` 로 붙인다(`5_현장시뮬_판_실제비율.py`). `--per-chat 1`.
- 프롬프트: 같은 구도·빛·옆 간판 그대로 · 표시선 지우기 · «Copy the artwork exactly, do not redesign» · 띠 비(19:1) · 음절 풀어 쓰기·ㅉ · «Output ONLY the facade photo».
- 🔴 **같은 안을 실제 비율 그대로 붙인 합성도 같이 낸다** — 표시선 길이(예: 6m = 436px)로 축척을 잡고 평면을 그대로 붙인다(파란 표시는 깨끗한 사진으로 메움, `fix_composite.py` 와 같은 법).
- 받은 그림은 간판 구역만 잘라 4장을 한 판으로 놓고 **철자·글씨체·크기·위치**를 본다.

**통과**: 철자 전부 맞음 · 사람에게 «AI 가 바꾼 것» 목록을 같이 보냄 · 실제 비율 그림이 있다.
**왜**: ChatGPT 4/4(88~94초)가 철자는 다 맞혔지만 **통통한 레터링을 일반 손글씨로 바꾸고, 간판을 실제보다 크게(띠 두껍게) 그리고, 한 장은 오른쪽으로 치우쳤다.** 10/10 에도 띠를 5~6:1 로 두껍게 그렸다. 실제 비율로 보면 띠 300 은 옆 가게 글자보다 작다 — 크기 판단은 실제 비율 그림으로만.
