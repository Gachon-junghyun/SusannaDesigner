# 3D 모델링 갈래 — 사진 속 건물·공간을 Blender 로 «사진처럼» (v0)

> **뭐냐:** 사진 몇 장(로드뷰·현장 사진)으로 실존 건물·파사드·매장을 Blender 에 짓는 순서. 단계마다 «해라» 명령과 통과 조건,
> 사람처럼 «하나 만들고 복사»하는 단축, 서브에이전트 쓰는 법, 렌더에서 볼 것. **v0** — 씨엘드레브 한 건(2026-10-07)에서 뽑았고 고칠 게 많다.
> **언제 읽나:** 사진에서 건물·공간을 모델링하기 «전»에 끝까지. 단계에서 막혔을 때 그 단계만 다시.
> 🔴 **매 건마다 아래 «시도 대기열»에서 하나 이상 새로 해 보고 결과를 «겪은 것»·단계에 반영한다**(`README.md` §작업할 때마다).
> **안 담는 것:** 그 한 건의 전 과정·숫자 → `STARTUP/model-lab/space/ciel/README.md` · 전문가 작업법·출처 → `STARTUP/model-lab/space/research_pro_workflow.md` ·
> Blender 5.2 API 함정 → `DeGaJa_Agent/module_render/BLENDER.md` · 사진 기하 함정 → `module_render/PHOTO.md` · 간판 디테일(베벨·나사) → `../study/2026-10-06_refs30/research_blender_detail.md`.

**원본 템플릿 = `STARTUP/model-lab/space/ciel/`** — 도구(`tools/`)·생성기(`geom/`)·씬(`scene/`)이 다 있다. 새 건은 이걸 복사해서 시작한다(§복붙).
**엔진 = `DeGaJa_Agent/module_render`** — `python -m module_render run <씬.py> -- …` 로만 렌더한다(종료코드 가드).

## 0. 먼저 가른다

| 받은 것 | 가는 길 |
|---|---|
| 벽 **한 면**만 (점포 하나, 간판 붙일 자리) | `/photo-model` — 정면화 + 벽 템플릿. 이 가이드는 과하다 |
| 건물 한 채·여러 면·입체 형태(아치·캔틸레버·경사) | 아래 1~10 |
| 실내(매장·로비) | 아래 1~10 그대로 — 면이 벽·바닥·천장일 뿐. 축척은 문 높이·카운터 같은 표준 치수로 |
| 사진 없이 «이런 느낌으로» | 이 갈래가 아니다 — 레퍼런스부터 모은다(`/errand`) |

**시작할 때 사람에게 한 줄 말해라:** «사진에서 나오는 건 모양과 비율이고, 절대 치수는 줄자 한 번이 필요합니다.»
(겹쳐 보기는 축척과 무관하다 — 세상과 카메라를 같이 키우면 그림이 같다. 모양 맞추기는 되고 견적은 안 된다.)

## 1. 작업 폴더를 복사해 세운다

**해라**
- `ciel/` 을 통째로 새 이름으로 복사하고 `ref/`·`work/`·`out/` 만 비운다. 도구와 생성기는 그대로 둔다.
- 사진을 `ref/` 에 PNG 로 넣는다(webp 는 변환). 해상도·출처를 README 머리에 적는다.
- 백그라운드 조사 에이전트를 **지금** 띄운다(§에이전트 ①) — 다음 단계들을 하는 동안 돈다.

**통과**: `python tools/gridcrop.py ref/1.png 0 0 W H work/g1.png 100 0.75` 로 격자 그림이 나왔다.

## 2. 사진을 진단한다

**해라**
- 격자 자를 얹은 확대(`tools/gridcrop.py`)로 **픽셀 좌표를 읽는다.** 모든 좌표는 이 자에서 온다.
- 수직 모서리 2~3개로 소실점을 낸다 → 사진 높이의 수십 배 밖이면 «수직 평행 = 수평 카메라 + 렌즈 시프트»(로드뷰는 대개 이것).
- 긴 수평선 몇 개의 휨(sagitta)을 잰다 → 1~2px 안이면 핀홀. 크게 휘면 파노라마 투영이라 이 가이드의 카메라 식이 안 맞는다.
- **수직이 보존되는 사진에서 기운 선을 찾아 적는다** — 그건 실제로 기운 부재다(씨엘드레브: 끝 날개 9°, 경사 기둥 7°).

**통과**: 사진마다 «카메라 모델 = 수평+시프트 / 일반» 한 줄.
**왜**: 수직이 평행인데 일반 기울어진 카메라로 풀면 초점이 틀린다. 기운 부재를 «사진 왜곡»으로 지우면 형태가 틀린다.

## 3. 선을 붙이고 소실점을 낸다

**해라**
- 방향(정면 수평 · 옆면 수평 · 수직)마다 **길고 확실한 경계 2개 이상**(지붕선·파라펫·창 띠). 끝점은 격자에서 ±3px 로 찍는다.
- `tools/refine_line.py` 로 경계에 서브픽셀로 붙인다(`tools/calib.py` 가 묶어 돌린다).
- 소실점은 직선들의 최소제곱 교점으로.

**통과**: 선마다 잔차 < 1px(씨엘드레브 0.28~0.89). 4px 넘는 선은 빼거나 상자를 좁힌다 — 경계가 둘 섞였다.

## 4. 카메라를 푼다

**해라**
- 사진이 **하나**면 `module_render._photo.level_camera(Vx, Vy, cx)` — fSpy 와 같은 식. 주점 x 는 가운데로 두고 결과를 «가정»으로 적는다.
- 사진이 **둘 이상**이면 `tools/solve_joint.py` 를 고쳐 쓴다: 두 사진에서 **같은 물리 점이 확실한 것** 5~9쌍(모서리·간판 끝·창 모서리)으로
  카메라 둘과 치수를 한꺼번에 최소제곱. 사선 사진의 주점 x 는 풀게 두고, 정면 사진의 주점 x 는 가운데로 고정한다.
- 미지수에 범위를 준다(초점 > 0, 카메라는 건물 앞).
- 카메라 높이는 가정 하나로 둔다(차량 로드뷰 2.5m) — 축척을 정하는 유일한 외부값이다.

**통과**: 재투영 rms < 3px. 화각이 로드뷰면 90° 근처(두 장이 따로따로 맞으면 좋은 교차 검증).
**왜**: 주점을 가운데로 가정한 한 장 해가 다른 사진과 1.8m 어긋났다(rms 7.5px). 같이 풀자 cx 가 100px 옆에 있었다(1.9px).
애매한 대응점 둘(«어느 창틀이 그 창틀인가»)을 빼자 rms 가 내려갔다 — 대응은 확실한 것만.

## 5. 치수를 역투영한다

**해라**
- **면을 아는 점만** 쏜다: 정면 = y 평면, 옆면 = x 평면, 땅 = z 0. `geom/scene_params.py` 처럼 한 파일에 모아 JSON 으로.
- 면을 모르는 부재(독립 기둥)는 두 사진의 모서리 여럿으로 단면 사각형을 푼다.
- **안쪽에 박힌 것(창·니치)의 높이는 그 깊이로 환산한다.** 올려 찍은 사진에선 안쪽이 낮아 보인다.
- 반복 간격(돌 줄눈·창 간격)은 **자기상관**으로 잰다 — 눈으로 센 값은 틀렸다(133px vs 실제 30px).
- 독립인 두 길로 같은 비율을 내 맞대 본다(씨엘드레브: «위 볼륨 폭 ÷ 포디움 높이» 두 사진 모두 2.62).

**통과**: 모든 치수에 출처(사진·픽셀·평면)와 «실측/가정»이 붙어 있다(`geom/params.json` 의 `_note`).
**왜**: 창 꼭대기를 겉면 깊이로 환산해 0.5m 낮게 지었다 — 렌더를 사진에 겹쳐 보고서야 잡았다.

## 6. 형태를 읽는다 — 가장 어렵고 가장 많이 틀린다

**해라**
- 해당 구역을 **명암 강조(equalize)** 해서 확대한다(사진·렌더 같은 픽셀 구역). 볼록·오목·테두리(립)가 여기서 보인다.
- **사선 사진의 «틈 비율»로 깊이를 계산한다**: 보이는 폭 = 창 폭 − 깊이·tanθ. 깊이를 감으로 정하지 않는다.
- 반복 단위 **한 칸의 수식**을 세운다(씨엘드레브: 두 칸에 걸친 교차 뾰족 아치 — 반지름 6.80m, 교집합 = 니치). 수식이면 변수 몇 개로 전체가 맞는다.
- **가설을 둘 이상 적고 둘 다 렌더한다** — 명령줄 스위치 하나로 바꿀 수 있게(`--arcade spoon|flat|pleat`). 그리고 나란히 본다.
- 결정한 근거와 «확정 못 함»을 README 에 같이 적는다.
- 새 눈 리뷰어를 띄운다(§에이전트 ②).

**통과**: 명암 강조 크롭에서 사진과 렌더의 «밝은 곳·어두운 곳 자리»가 같다. 경계 점수로 통과시키지 않는다(§9).
**왜**: 아치 면을 평평한 니치 → 오목 주름 → 숟가락으로 세 번 고쳐 읽었다. 경계 F1 은 셋을 못 갈랐고(0.42·0.43·0.42),
나중엔 버린 쪽이 더 높게 나왔다(0.659 vs 0.589). 처음 해석에 매달린 시간이 제일 비쌌다.

## 7. 부품으로 나눠 짓는다

**해라**
- 건물을 **부품 목록**으로 쓴다: 덩어리 · 반복 모듈(아치 칸) · 외장(석재) · 개구부(창·문) · 처마·천장 · 기둥 · 식재 · 사인 · 땅.
- 부품마다 **생성 함수 하나 + 근접 카메라 하나**(`--cam bay|corner|void|fins`). 부품을 근접에서 먼저 확인하고 합친다.
- 반복 모듈은 **한 칸을 정성껏** 만들고 복제한다(§복붙).
- 면은 `module_render._facade` 로 짓는다: `Face`(입면 좌표 a·z + 깊이) · `poly_slab`(다각형 → 판, 반두께·베벨 보정 내장) ·
  `stone_wall`(판 한 장씩, 줄눈이 실제로 빔) · `rect_window`(틀·살·유리).
- 복잡한 2D 형태(아치·잎)는 호스트 파이썬 shapely 로 다각형을 만들어 JSON/npz 로 넘긴다(`geom/arcade.py`). 곡면은 «경계까지 거리»로 깊이를 준다(`geom/pleat.py`).
- 창 뒤에는 **볼 것**(실내 상자·커튼)을 둔다. 속(코어) 상자는 **개구부 뒤**에 둔다.

**통과**: 근접 렌더마다 그 부품의 2차 디테일(테두리 둥글기·줄눈·창살·커튼)이 보인다.
**왜**: 속 상자를 석재 바로 뒤에 뒀더니 1층 문·창·핀 칸이 전부 회색 판이 됐다(에러 0). 근접 렌더가 없었으면 «원래 그런가» 했다.

## 8. 사진 카메라로 조립하고 빛을 맞춘다

**해라**
- `module_render._scene.camera_match(f, cx, cy, W, H, yaw_rad=…, location=…)` 로 사진 카메라를 그대로 세운다.
  씬이 사진 점 몇 개를 되찍어 오차를 출력하게 한다(`### PROJ` — 1~2px 안이어야 한다).
- **덩어리부터** 겹쳐 본다(상자 수준) → 맞으면 디테일. 순서를 거꾸로 하지 않는다.
- 해 방향은 사진에서 뽑는다: **어느 면이 더 밝나** + **땅 그림자가 어느 쪽인가**.
- 하늘/해 균형은 사진의 **면 밝기 비**(양지/그늘)에 맞춘다: `tools/regions.py` 로 재고 하늘을 낮추고 해를 올린다(씨엘드레브: 하늘 0.08 · 해 10 · AgX 노출 −0.4).
- **해를 끈 렌더와 대조해** 해가 실제로 닿는지 확인한다.
- 카메라에 보이는 하늘만 사진 색 그라디언트로 바꾼다(`Light Path › Is Camera Ray`) — 조명은 물리 하늘 그대로.
- 바닥재는 거칠기 높은 것으로, 줄눈은 텍스처로.
- **새 물건을 사진에 얹는 «후» 그림은 맥락을 짓지 말고 사진을 쓴다**(해 봄 · 한 건, 고객J): 모델 전체를 그림자 받이(`is_shadow_catcher`) + 필름 투명으로 두고, 새 물건·지운 자리 패치만 정상 렌더 → 사진 위에 합성(`model-lab/space/clientj/tools/composite.py`). 노출은 패치 벽 ↔ 사진 벽 화소 중앙값 비를 렌더 전체에 곱한다. 받이 형태가 틀리면 지운 물건이 되살아나므로 **지울 물건 앞의 받이(차양 등)는 사진으로 푼다.** 야간은 렌더 카메라 = 사진 카메라에서 `TexCoord.Window` 로 사진을 albedo 투영.

**통과**: 벽·하늘 영역 밝기가 사진의 0.9~1.1배, 양지/그늘 비가 사진과 ±0.05.
**왜**: 물리 하늘 0.5 가 해 4.5 를 삼켜 해 기여가 2~6% 였다(«흐린 날»로 멀쩡해 보였다). 스캔 화강석 바닥은 하늘을 거울처럼 비췄다.
해를 놓은 직후 방향을 찍으면 갱신 전 값이 나온다 — `view_layer.update()` 뒤에 찍는다.

## 9. 숫자로 대조한다

**해라**
- `tools/overlay.py <사진> <렌더> <접두> --mask …` → 나란히·50% 겹침·경계 그림 + 경계 F1·챔퍼 거리.
- `tools/regions.py` → 면별 밝기 비.
- 명암 강조 크롭 나란히(§6).
- 사실감 요소를 **하나씩 끈** 렌더 묶음을 백그라운드로 돌리고(`tools/batch_final.sh` 형식) `tools/ablation.py` 로 표를 만든다.

| 무엇을 알고 싶나 | 쓸 것 |
|---|---|
| 덩어리·배치·개구부 자리 | 경계 F1(3px) |
| 해 방향·노출·하늘 균형 | 면 밝기 비 |
| 볼록·오목·테두리 | 명암 강조 크롭 나란히 + 새 눈 리뷰어 |
| 디테일이 이 거리에서 보이나 | 요소 끄기 «화면 변화» |

**통과**: 경계 F1 이 사진마다 적혀 있고, 형태 판단 근거가 F1 이 아닌 다른 것으로 적혀 있다.
**왜**: 경계 F1 은 해를 꺼도 오르는 등 «경계의 양»에 반응한다 — 형태 정답을 가리지 못한다.

## 아직 모르는 것 (v0 의 빈칸)

- **새 눈 리뷰어(②)가 형태 오독을 실제로 줄이나** — 안 해 봤다. 다음 건에서 6단계에 넣고 결과를 여기 적는다.
- **형태를 숫자로 가르는 지표** — 경계 F1 은 못 한다. 후보: 면 방향별 밝기 분포 대조, 명암 강조 이미지끼리 상관.
- **모서리·끝 처리** — 사진 해상도로 못 정했다(씨엘드레브 모서리 1m 민 블록).
- **주변 맥락**(나무·차·전선) — 사진과 남은 위화감의 대부분인데 단계가 없다.
- **실내** — 한 건도 안 해 봤다. 축척을 표준 치수로 잡는 4~5단계가 실내에서 그대로 되는지 모른다.
- `tools/solve_joint.py` 는 씨엘드레브 점에 맞춰 손으로 고쳐 쓰는 스크립트다 — 일반 도구가 아니다. `refine_line.py`·`overlay.py` 는 두 건째에 쓰이면 `module_render` 로 올린다.
