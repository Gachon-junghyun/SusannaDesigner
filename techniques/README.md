# techniques — 기법 대장 (표현 방법 한 가지씩)

> **뭐냐:** 결과물을 «어떻게 표현하나»를 기법 하나당 카드 한 장으로 모은 곳. 스타일(`../styles/`)이 «무엇을 어떤 값으로 조합한 결»이라면, 기법은 그 결을 만드는 **부품**이라 다른 스타일에도 갖다 쓴다.
> **언제 읽나:** 사람이 «무슨 기법 있지», «X 스타일에 Y 기법 적용해 봐», «좀 심심한데 뭘 더 할까»를 물을 때. 새 스타일을 시작하기 전. 한 건을 넘긴 뒤(새 기법이면 카드, 있던 기법이면 손잡이·함정 한 줄).
> **안 담는 것:** 스타일 조합과 값 → `../styles/` · 단계 → `../protocols/` · 날짜순 시행착오 원문 → `../LESSONS.md` · 아직 안 해 본 시도의 채점 → `../CHALLENGES.md`.

## 추천할 때 (사람이 «무슨 기법 있지», «뭘 더 할까»)

1. **목적·분위기로 먼저 고른다** — 아래 표에서 두세 개를 골라 «무엇이 되나 + 예시 그림»으로 보여 주고, 지금 결과물에 얹으면 어떻게 되는지 한 줄씩 말한다.
2. **스타일과 어울리는지 본다** — 어울림 표. «안 맞음»을 고르면 이유를 말하고 그래도 원하면 저해상도로 먼저 보여 준다(`protocols/modeling.md` §조형물·곡면 4 와 같은 원칙: 한 마디 지시는 미리보기로 확인).
3. **새 시도 하나는 같이 권한다** — 아래 «미검증 후보»에서 하나. 해 보면 결과를 카드로 올리거나 «안 됨»과 이유를 남긴다.

## 미검증 후보 (아직 안 해 봄 — 추천할 땐 «처음 해 보는 것»이라고 말한다)
- 하프톤 점(그림을 크기 다른 점 격자로) · 리소그래프 두 색 겹침(어긋남 포함) · 디더링 픽셀(1비트) · 글리치(줄 밀림·색 갈림) · 블루프린트 선화(파란 바탕 흰 선, 치수선) · 지형 등고선(그림 밝기를 등고선으로) · 문자 아트에 평면 다섯 색 입히기

## 쓰는 법
- **새 기법**(목록에 없는 표현 방법으로 결과물을 냈으면): 넘긴 같은 턴에 카드(`_TEMPLATE.md`)와 예시 그림(`_img/`), 목록 한 줄, 추천 표에 한 줄. 미검증 후보에서 왔으면 그 줄을 지운다.
- **있던 기법을 다시 썼으면**: 손잡이 값이 새로 알게 된 효과면 «손잡이» 표에, 밟은 것이면 «함정»에 한 줄(항목 하나씩).
- 스타일 카드의 «쓴 기법» 칸이 여기 카드를 가리킨다. 둘 중 하나만 고치지 않는다.
- 도구는 경로로 부른다. 두 번째 건에서 쓰게 되면 `forge/lib`·`ad/` 로 올리고 카드의 경로를 고친다.
